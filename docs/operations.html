    Operations

    Keep the capture service predictable: local bind mounts, one writer, explicit exporter ports, and retention rules you can inspect.

    Data folders and bind mounts

    FolderContainer pathPurpose
    nfsen-data//var/nfsen/profiles-dataRaw NetFlow capture files
    nfsen-stat//var/nfsen/profiles-statRRD graph files and charts
    nfsen-var//var/nfsen/varLogs, cache, and runtime state
    nfsen-etc//var/nfsen/etcConfig, sources, and auth files
    Backup boundary

    Back up all four folders for a complete restore. Never export nfsen-etc/ to an untrusted host because it contains password hashes.

    tar czf nfsen-backup.tar.gz nfsen-data nfsen-stat nfsen-var nfsen-etc

    Managing router sources

    Ports 2055 and 2056 are exposed by default. To add a router on a new port, publish the UDP port in docker-compose.yml, add a matching source to nfsen.conf, reconfigure, and restart:

    services:
  netlens:
    ports:
      - "2070:2070/udp"
    docker exec netlens /var/nfsen/bin/nfsen reconfig
docker compose up -d
    Source names matter

    Keep source identifiers short and stable. LibreNMS matching replaces dots with the configured split character and NfSen idents are limited to 21 characters.

    Password protection

    docker exec netlens htpasswd -b /var/nfsen/etc/.htpasswd admin YourNewPass123

    Use a strong unique password and put the dashboard behind a VPN or reverse proxy with TLS when it is reachable outside a trusted network.

    Data retention

    Open Profile Admin → live profile → Edit in NfSen. Set the retention window and maximum storage size, then save. The daemon applies the limits in the background.

    Storage planning

    Raw flow files are the fast-growing part of the stack. Watch disk usage after the first busy collection window and choose retention from observed volume.

    Troubleshooting

    No flow files

    1. Confirm the router exports NetFlow v5, v9, or IPFIX to the host IP.
    2. Confirm the correct UDP port is published and allowed by the firewall.
    3. Check the source port in nfsen.conf and reconfigure the daemon.
    4. Inspect docker logs netlens and nfsen-data/live/.
    docker compose ps
docker logs --tail=100 netlens
find nfsen-data/live -maxdepth 2 -type f | head

    LibreNMS shows no Netflow tab

    Use the LibreNMS integration guide checklist. Common causes are an empty nfsen_suffix, a wrong source/device name, incorrect nfsen_subdirlayout, or an nfdump version mismatch.

    Security notes

    • Keep nfsen-etc/ private and never share it over NFS.
    • Export only nfsen-data/ and nfsen-stat/, read-only, for LibreNMS.
    • Do not run two NfSen instances writing to the same live folder.
    • Restrict UDP exporters and TCP 8070 to known networks where possible.
